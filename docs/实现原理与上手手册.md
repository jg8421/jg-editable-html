# 可批注 HTML：实现原理与上手手册

> **这份文档给谁**：拿到 `jg-editable-html` 技能包、想自己做出「可批注 / 可就地编辑 / 可就地保存」的单文件 HTML 的人（含让 AI 代为执行）。
> **配套文档**：`可批注HTML_收件人一页说明.md`（发给阅读者用的操作说明）、`SKILL.md`（给 AI 的执行规程）。
> **一句话**：面板本身仍是**零依赖单文件**，只是额外注入了三块东西 —— **锚点定位、页内 UI、数据写回文件自身**；不需要服务器、不需要数据库、不需要联网。

| 文件 | 作用 | 说明 |
|---|---|---|
| `SKILL.md` | 给 AI 的执行规程 | 什么时候用 / 怎么用 / 坑 |

## 2. 整体架构：三层，数据随文件走

```
目标面板.html（原本就是零依赖单文件：内联 CSS + 手写 SVG + 原生 JS）
│
└─ 在 </body> 之前注入三块（注入器写入，重复注入会先删旧的 → 幂等）
   ├─ <script id="pv-notes-data" type="application/json">{}</script>   ← 数据占位
   ├─ <script id="pv-notes-module"> …pv-notes.js 全文… </script>       ← 模块本体
   └─ <script> …自测脚本… </script>                                    ← 仅 --test 时注入，交付绝不带
```

- **数据存在文件里**：批注、文字修改、冻结区都写进 `pv-notes-data` 这个 JSON 块。**文件发给谁，批注就跟到谁**；对方在副本上继续加，发回来能按 id 合并。
- **UI 不进文件**：批注界面是模块运行时创建的（`<div id="pvnt-root">`），保存时会被剥掉，打开时重新生成 —— 所以不会越存越臃肿。
- **保存后文件变大是正常的**：面板正文若是 JS 在解析期渲染出来的，第一次保存会把渲染结果一并固化（例如 76 KB → 86 KB）；此后再保存**不再增长**（面板用 `innerHTML` 覆盖渲染，不追加）。

## 3. 每一层是怎么实现的

### 3.1 锚点：不记行号，记「原文 + 上下文 + 偏移」

选中一段文字时，模块把选区换算成一个**与 DOM 结构无关**的锚点（`anchorOfRange()`）：

```js
{ sec: 容器 id,  off: 字符偏移,  snippet: "选中的原文",
  pre: "前 40 字",  post: "后 40 字",  label: "章节名" }
```

定位时（`locate()`）按「容器 → 全页」两个作用域顺序找：先找出 `snippet` 在纯文本里的**所有**出现位置（上限 300 处），**能用 `pre` 精确匹配的优先**，否则取与记录偏移 `off` 最近的那个。

- 好处：面板改版、加了一段话、重排了表格，批注**仍然定位得到**。
- 定位失败**不静默丢**：抽屉里标红「定位失效」，导出 .md 时也写「← 定位失效（原文可能已改写）」并附上原文。

### 3.2 高亮与页内 UI

- 高亮用浏览器原生 **CSS Custom Highlight API**（`CSS.highlights`，两个高亮名 `pvnt-note` / `pvnt-act`）——**不修改正文 DOM**，所以不会干扰面板自己的渲染与事件。
- UI 全部挂在 `#pvnt-root`（`position:fixed`，`pointer-events:none`，子元素单独放开）：右缘竖标签、抽屉、选中后浮出的「＋ 批注」、右下角提示。
- **事件隔离**：UI 上的 click / mousedown / wheel / keydown 全部 `stopPropagation`，不会误触发面板自己的全局点击委派或滚轮行为（实测 `leakBubble=0`）。

### 3.3 就地改字

双击文字 → 该元素临时 `contenteditable` → 失焦提交（`commitEdit()`），记录 `{a, a2, old, next}`（改前 / 改后的锚点 + 新旧文本）：

- **只允许在叶子元素上编辑**（`children.length === 0`），避免把整个容器的内容抹掉；
- **重放前必须校验**当前文本等于 `old`（`reapplyEdits()`），不等就跳过 —— 绝不误改；
- 撤销（`undoEdit`）同样先校验当前文本等于 `next` 才写回 `old`。

### 3.4 块编辑 v2.0（删表格 / 调顺序 / 加行加列）

抽屉里打开「✎ 编辑」后，鼠标悬停任意块（段落 / 标题 / 列表 / **表格** / 图 / 卡片 / 整个 section）浮出工具条：`⬆ 上移  ⬇ 下移  ⧉ 复制  </> 源码编辑  ✕ 删除`；表格另加 `＋行 / －行 / ＋列 / －列`；`＋段落 / ＋表格` 在下方插入。`Ctrl+Z` 撤销 15 步（内存 `undoStack`）。

**为什么需要「冻结」**：这类面板的正文往往是面板自己的 JS 在解析期算出来的（`box.innerHTML = h`）。**你删掉的表格，下次打开一渲染就又回来了** —— 这才是「HTML 改不动」的真正原因。

### 3.5 冻结保护：让用户的改动永远赢

任何结构改动，都把「**最近的带 id 的祖先容器**」整块 `innerHTML` 快照存进 `frozen[]`，然后：

- **加载顺序**（`init()` 内的确切次序）：
  `buildUI() → load() → applyFrozen() → reapplyEdits() → renderAll()`，
  即**面板渲染完之后**再把冻结内容塞回去；
- 再用 **MutationObserver**（`watchFrozen()`，60 ms 防抖）盯着这些容器：面板若把它们重绘掉就塞回来，**连续 8 次仍被覆盖就放弃并提示**（防止和 3D 自动旋转之类互相刷 CPU）；
- 抽屉里有 `🔒 已编辑并锁定 N 个区域 [全部还原为原始]`，一键回到原始版本。

**取舍（必须如实告知使用者）**：冻结粒度是「带 id 的整块」，所以**冻结区域里面板自身的交互会失效**（例如切图表的按钮），因为监听器随 `innerHTML` 替换一起没了。粒度不能再细 —— **面板的重绘单位就是带 id 的元素**。

### 3.6 保存回文件（Ctrl+S）

`keydown` 在**捕获阶段**拦截 Ctrl/Cmd+S（在批注输入框里按也生效）→ `doSave()`：

1. 内存里有文件句柄 → 直接用；
2. 没有 → 查 **IndexedDB**（库 `pvnotes`、store `h`，key = 去掉 hash 的 `location.href`，值 = `FileSystemFileHandle`）→ **跨会话记住**；
3. 仍然没有 → 弹**一次** `showSaveFilePicker`（`suggestedName` = 当前文件名）；
4. 写之前 `handle.requestPermission({mode:"readwrite"})`（**已授权时立即返回、不弹窗**）；
5. `createWritable() → write(html) → close()`，然后刷新状态条与 toast。

- **刻意不产生副本**：写回的是**同一个文件**，不会出现「_批注版_v2」。
- **兜底**：浏览器不支持 File System Access（Safari / Firefox）或写失败时，**下载一份副本**并明确提示，绝不假报成功。
- 另有并发闸 `saving`（连按两次不会弹两个框）与 `beforeunload` 未保存提醒。
- **唯一绕不过的**：网页无权写自己所在的文件 → **每次打开文件后的第一次保存必须授权一次**。这是浏览器安全模型，不是实现缺陷。

### 3.7 数据格式与回流（给下一版用）

```json
{
  "pvnotes": "1.0", "author": "批注者", "savedAt": 1757...,
  "notes":  [{ "id","sec","off","snippet","pre","post","label","text","author","ts","status" }],
  "edits":  [{ "id","a","a2","old","next","author","ts" }],
  "frozen": [{ "id","html","ts" }]
}
```

- 读取时**白名单净化**（`sanitize()`）：只保留认识的字段，脏数据直接丢弃；
- 双源合并（`mergeStates()`）：文件内嵌 JSON 与 localStorage 两个来源**按 `savedAt` 取新**，批注 / 冻结区**按 id 逐条取时间较新者**，`edits` 只做补齐不覆盖；
- **回流到下一版**：把 `notes` 按锚点在新版落位（找不到就标 orphan 并附原文）、把 `edits` 的 `old → next` 直接改进正文，然后**清空 `edits`、保留 `notes` 并标「已处理」**，再重新注入新版。

## 4. 自己做一个可编辑 HTML：六步

```powershell
# Step 2 注入（幂等：重复注入会先删掉旧的注入块）
python "<技能目录>\assets\inject_pvnotes.py"  成品.html  成品-可批注.html
# 注：--test 会额外注入自测脚本，只在验证时用；交付文件绝不能带

# Step 3 模块语法校验（可选，需要 Node）
node --check "<技能目录>\assets\pv-notes.js"
```

**Step 1 · 写面板**（或拿到已有的单文件面板）
单文件、离线、零依赖；**给每个正文板块的容器加 `id`**（锚点与冻结都挂在这个 id 上，`section id="..."` 最好）；正文不要用 `contenteditable`、不要在 `<script>` 里放会与模块冲突的全局点击委托。

**Step 4 · 渲染验证**（Chrome 无头，注意参数写法）
```powershell
$single = "--headless=new --disable-gpu --no-sandbox --user-data-dir=C:\Temp\ud --virtual-time-budget=9000 --dump-dom $url"
Start-Process -FilePath $chrome -ArgumentList $single -Wait -RedirectStandardOutput $out
```
⚠️ `-ArgumentList` 必须传**一个完整字符串**；传字符串数组会被解析成多个 target，报 `Multiple targets are not supported in headless mode`。

**Step 5 · 端到端往返验证（关键，别靠肉眼）**
把探针挂在 `<head>` 末尾（用 `src.rfind("</head>")` **只替换最后一次**），在页面里断言：

```js
PVNotesType=object / PVNT_EDIT=object / document.querySelectorAll("#pvnt-root").length === 1
addNoteAt(sec, 片段, "测试") → items 增加 / CSS.highlights.get("pvnt-note").size 增加
var out = PVNotes.buildOutput();   // 产物必须：不含批注 UI、含 pv-notes-data、以 <!doctype 开头
```
再把 `out` 落盘 → **新进程重开**：断言批注条数、`locate()` 全部命中、section 照常渲染、`#pvnt-root` 仍然只有 1 个。

**Step 6 · 交付前清理**：去掉自测脚本 → 复跑 Step 5 的容器审计 → 确认产物里**不存在 `<div id="pvnt-root">` 这个标签**。

## 5. 验收清单（每条都可用一条命令或一次断言验掉）

- [ ] `window.PVNotes` 与 `window.PVNT_EDIT` 都是 object（编辑器已初始化）
- [ ] `#pvnt-root` 恰好 1 个（不重复注入、不重复初始化）
- [ ] 选中文字 → 浮出「＋ 批注」→ 写入后列表 / 高亮 / 计数同步
- [ ] 双击改字 → 记录 → 「还原」能回退
- [ ] `locate()` 对每条批注命中（跨章节也能滚动到位，落点不被吸顶导航盖住）
- [ ] `buildOutput()` 产物**不含** `<div id="pvnt-root">`、**含** `pv-notes-data`、以 `<!doctype` 开头
- [ ] 保存产物**重开**后：批注全在、修改仍是改后状态、`#pvnt-root` 只有 1 个、正文照常渲染、控制台无报错
- [ ] 再次保存长度不增长（DOM 幂等）
- [ ] 交付文件里没有自测脚本（搜索 `pvnt-selftest` 应为 0）
- [ ] 移动端 / 小窗口不出现横向溢出

## 6. 已踩过的坑（照单避让）

| # | 坑 | 现象 | 处理 |
|---|---|---|---|
| 1 | 文本节点边界 | 撤销/重放时 `p.textContent = old` **把整个容器内容抹掉** | `posAt()` 在 `pos === acc+L` 时必须返回**下一个**文本节点的 `off=0` |
| 2 | 选区起点是元素 | `selectNodeContents()` 的 `startOffset` 是**子节点序号**不是字符偏移 → 垃圾锚点 | 用 `pointOf()` 换算成（文本节点, 字符偏移） |
| 3 | 编辑范围太宽 | 误改容器 | 只在 `children.length===0` 的叶子元素上编辑；重放前后校验文本 |
| 4 | 平滑滚动打断 | 「点了没反应」 | 定位时先把 `scrollBehavior` 临时改 `auto`，`scrollTo` 后 80 ms 还原；偏移取 `scroll-padding-top` |
| 5 | **探针注入炸模块** | 出现 `PVNotes === undefined`、UI 不见了，像是模块坏了 | `pv-notes.js` 头部注释里含 `</body>` 字样 —— **必须 `rfind("</body>")` 只替换最后一次**，或在 `<head>` 挂探针 |
| 6 | **自测断言被自己命中** | 明明剥干净了却报「UI 没剥掉」 | 断言关键词要**拼接**（`'<div' + ' id="pvnt-root">'`）；判断产物看**标签**不看裸字符串 |
| 7 | 交付带了 `--test` | 正式文件里出现「定位失效」之类自测残留 | 交付一律不加 `--test` |
| 8 | 初始化顺序 | 编辑器静默不加载（`PVNT_EDIT === undefined`） | 必须 `window.PVNotes` 赋值**之后**再调 `window.__PVNT_EDITOR__()` |
| 9 | 保存后又变脏 | 状态显示与实际相反，每次关页面都提醒 | `saveLocal()` 里**绝不能**把 `dirty` 置回 true |
| 10 | 无头环境测 IndexedDB 出错 | 误判「file:// 下 IDB 被禁用」 | `--virtual-time-budget` 会虚拟化定时器而 IDB 走真实 I/O → 用 CDP 真实等待后再断言 |
| 11 | 冻结区交互失效 | 点了没反应 | 这是快照语义的必然代价，明确告知 + 提供「全部还原为原始」 |

## 7. 兼容性与边界（一次说清）

| 能力 | Chrome / Edge（file:// 或本地） | Safari / Firefox |
|---|---|---|
| 批注、就地编辑、导出 .md | ✅ | ✅（数据与导出不受影响） |
| 当前句高亮（CSS Highlight API） | ✅ | 部分浏览器/旧版本可能不显示（不影响数据，定位仍可用） |
| **Ctrl+S 原地写回同一个文件** | ✅（File System Access API） | ❌ → 自动退化为「下载副本」，并提示 |

- `file://` 是**安全上下文**，`showSaveFilePicker` / `IndexedDB` / `localStorage` / `CSS.highlights` 均可用；**OPFS（`navigator.storage.getDirectory()`）在 `file://` 下不可用**（`SecurityError`），所以本方案不用它。
- 数据全部留在**本机浏览器与这个文件里**，不上传任何服务器。
